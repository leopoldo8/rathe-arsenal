# Card alternatives implementation notes

## Deviations

Each is the conservative choice, logged, with the build kept going.

1. **C36, "every deck in the readiness suite".** The proof runs the test alone with `-t`, so a test that replays the inputs of the other tests would see none. The test replays a table of eight decks that cover every branch of the compute (all owned, tier 1 and tier 2 stand-ins, rejected and approved swaps, hero and weapon slots, a card missing from the catalog, a card split across slots), once without the protected input and once with an empty one. `readiness.spec.ts` was only appended to.
2. **Generic group score (plan says none).** `generic` scores a candidate with the tier 2 scorer on a copy of it that takes the missing card's classes and talents, with no floor. Its six gates are the Generic class, the same pitch, a shared type, the same equipment body slot and a power and a defense gap of at most 2. The score only orders cards inside the group.
3. **C4, "a zero-keyword-overlap candidate with power delta 2 is accepted".** That holds when the missing card has no keywords (score 0.70, exactly the floor). A missing card with keywords and zero overlap scores 0.55 at power delta 2 and is rejected, so the test uses a missing card without keywords and adds a case with keywords and delta 0 (score 0.85, accepted in `close`).
4. **C9, Silver Age rarity rows (corrected after verification round 2).** The first text said the real catalog has no card that reaches the rarity rule. That was false: `blade-dance` (Marvel rarity, a token, legal in Silver Age) breaks it for young heroes such as `dorinthea-quicksilver-prodigy`, `boltyn`, `hala` and `kassai`. The two rows now use `blade-dance` and assert `rarity_not_allowed`; no equipment card reaches the rule, so the equipment row uses it too. The synthetic test stays.
5. **C16, `q=sink`.** No card that only contains "sink" is legal for Katsu, so the test uses `dash-io`, for whom `aether-sink-yellow` is legal.
6. **Existing specs adapted to the new behaviour, assertions unchanged.** `substitution.service.spec.ts` asserted the exact argument list of `computeEffectiveReadiness` (now seven arguments); the four `DecksService` specs and the substitution spec gained a provider for `ReplacementsQueryService`; deck detail fixtures gained `replacements: []`.
7. **C64 and C34 recompute trigger.** `POST /api/collection/cards/batch` does not recompute deck readiness, so the e2e tests mark a card owned afterwards (the recompute path the check names). C64 owns three copies of the stand-in because the deck's other missing card is served first.
8. **Name of an original on the deck page (resolved after verification).** The first build derived the name from the identifier, wrong for 8.1% of cards (404 of 4,979: `A Moments Peace`, `Arakni Redback`). The orchestrator decided under the plan's additive-Surface rule: each `replacements[]` entry now carries `originalName`, the catalog name (the identifier when the card left the catalog), the marks render it and the identifier-derived helper was deleted. The plan's Surface row for `GET /api/decks/:deckId` had the field appended.
9. **Module placement.** The reads and the close-as-removed update live in `ReplacementsQueryService` (leaf `ReplacementsCoreModule`), so `SubstitutionModule` and `DecksModule` import it without a cycle, the way `SwapsCoreModule` works for swap rows. No hop of the Flow changed.
10. **`-swaps.test.tsx`.** The check names a file that did not exist (the existing page test is `swaps.test.tsx`); a new small file with that name holds the proof.
11. **Throttle spec.** The throttle checks send 121 requests per route that end in 400, 404 or 409 (the guard counts them all), so no real picks are made.
12. **The 0.05 owned bonus** is pinned as the plan says; no real decks are reachable from here to calibrate it (open question 1 stays open).
13. **Checks extended after verification.** New members were appended, no wording changed: C17 (request without `cardIdentifier`, without `slot`), C43 (body without `originalCardIdentifier`, without `pickedFrom`), C55 and C56 (a name with punctuation), C59 (`originalName`), and service-layer proofs for the decision table appended to C32, C39, C40 and C45 (five illegal causes, retirement over pending, approved and rejected, the four row shapes in pick and revert). The C44 and C67 specs now assert `owned: true`, `reverted` and `kept`; both faults the Verifier found were re-injected and fail the spec.
14. **C58 and the fixture.** The proof failed because the fixture, not the feature: on the current card data a fresh `pnpm seed:fixture` user already gets 1 pending swap instead of 3, with no pick or undo. The first swap is tried while every other missing copy counts against the pitch-curve tolerance (red 2, yellow 1, blue 1), and the fixture left yellow and blue gaps of 2, so the first swap was rejected. The first attempt owned more cards, which changed the library page and broke its visual baseline, so the seed now trims the deck instead: the swap deck leaves exactly red 3, yellow 1 and blue 1 missing (Brothers in Arms x3, Bear Hug x1, Argh Smash x1), the owned set is as it was, and the three swaps return. `MIN_PENDING_SWAPS` is unchanged. This also unbroke main's own Playwright suite on the new card data.
15. **Manual source under concurrency (pre-existing, card-scanner).** Confirmed: on a schema TypeORM `synchronize` manages (local dev, the e2e database) 30 concurrent first writes for a fresh user created 30 `manual` sources, because the partial unique index `IDX_csv_source_user_manual_uq` exists only in the migration, which `synchronize` never runs. Each source capped a card at 20 separately, hence the 28 seen once. Production runs the migration and has the index, so the catch on `23505` in `ensureManualSource` works there. The entity now declares the same index, with a spec that failed (30 rows) before. Same gap, not fixed: `IDX_csv_source_user_content_hash_uq` is also migration-only. A staging database that was ever written with `synchronize` and already holds duplicate manual sources would fail to create the index at boot of a `synchronize` run; none exist in the local database.
16. **407 and the flaky throttle spec.** The `407` was not reproduced here (no proxy variable is set; 8 isolated throttle runs and 4 full runs with the dev server stopped were clean at first). What did reproduce, in about 40% of isolated runs of `replacements-throttle.e2e-spec.ts` (5 of 12, then 4 of 10, also with the sandbox off), was a test that stopped early: `read ECONNRESET` on one request, or a 121st request that was not throttled. A tracker spy showed the guard saw every request that was actually sent, all from `::ffff:127.0.0.1`, so the app was counting correctly; the failures come from supertest opening and closing a listening server for each of the 600 requests of a run when the app is only `init`ed. The replacements fixture now calls `app.listen(0, '127.0.0.1')` once, the way `card-scanner-throttle.e2e-spec.ts` does: 0 failures in 25 runs of the probe and 0 in 12 of the real spec afterwards. No retry was added and no assertion loosened. The `407` the Verifier saw is most likely the same per-request listen churn meeting the sandbox network filter; sign-up, GET and POST routes were all hit, so it is not tied to a request pattern. With `pnpm dev` running next to the suite, 2 of 3 full runs had one to five such failures before the fix.
17. **Checks extended after verification round 2.** New members appended, no claim reworded (see each check's trailing text): every `pickedFrom` value stored and returned (C32); `hasQuery` false (C21); the index and the user cascade under C52's named proof, with the entity declaring the migration's index name, plus a spec that builds the schema from the entities and proves the 8 CHECKs by name (added to C52); two-slot marks (C55, C56); every DTO validator at its bounds and a non-integer deck id (C17, C43); the `originalName` fallback under C59's proof; `blade-dance` rarity rows (C9).
    - Validators walked in the range: pick body `originalCardIdentifier`, `slot`, `replacementCardIdentifier` (`@IsString`, `@IsNotEmpty`, `@MaxLength`) and `pickedFrom` (`@IsIn`); alternatives query `cardIdentifier`, `slot`, `q`; route params `deckId` (alternatives, pick) and `id` (revert, keep, covered by C48). All now have a boundary case.
    - A real bug surfaced: `OwnsTrackedDeckGuard` runs before `ParseIntPipe`, so `/api/decks/abc/...` reached Postgres as NaN and answered 500 on every deck route. The guard now answers 400. The Verifier's fault Q5 (removing `ParseIntPipe`) is therefore an equivalent mutant: the guard answers first. Removing the guard's check instead is killed (guard spec and e2e).
    - Faults re-injected and killed: constant `pickedFrom` and a dropped `search` value, constant `hasQuery`, the migration's index and cascade removed, slot comparisons replaced in the deck list and missing panel, `@MaxLength(64)` and `@IsNotEmpty()` on `slot`, `@MaxLength(128)` on the query `cardIdentifier`, the guard's integer check, each CHECK decorator removed (two tried), the rarity rule neutralised, the `originalName` fallback changed.
18. **e2e and int harnesses.** `app.listen(0, '127.0.0.1')` once instead of `app.init()` in `plan-b-full-flow`, `theme-persistence`, `swaps.controller`, `auth.controller`, `admin-stores.controller`, `decks.meta` and `re-solve.controller` e2e specs, and in the `decks` post, put, patch and `tags` int specs. `manual-source-concurrency` sends no HTTP and is unchanged.
19. **Checks extended after verification round 3.** Members appended, no claim reworded (each check's trailing text): C52 widths and the entity index name; C12, C40 copies in two slots; C44 quantity and owned; C32 and C35 duplicate rows; C49 the equipment slot and the save response; C59 PUT and scratch-create responses; C14 a failing store query; C56, C57, C65 wiring and error toasts; C58 the mark in the missing panel; C17 deck ids outside int4.

The selection now happens in an effect on mount; a test that runs the late frame between two keystrokes fails on the old code and passes now.
