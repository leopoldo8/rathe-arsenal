- **Row-order blindness (new C34).** Before this fix `buildSheet` kept existing rows first and shuffled only the newly added batch, so the first 30 rows of the committed sheet are exactly the heuristic's cards, and the judge page showed rows in sheet order. The committed `out/judging-sheet.csv` and `out/result.md` are the owner's record and were not modified. **Limitation of the recorded result:** the 30 heuristic rows were judged as the first block of each deck (10 per deck), so the comparison between the heuristic and the models is confounded by position. The comparison among the four language models is unaffected, because their 70 rows were shuffled together. For any future rebuild, `buildSheet` orders all rows by one seeded shuffle over the full (deck, card) set (taken from a canonical ordering, so history does not matter), keeping verdicts per pair. The judge page shows rows in sheet order, which after a rebuild is that same position; it does not re-sort them, because the approved C33 test asserts the payload row order equals the sheet order.
- **C23 re-expressed by pair, not by position:** the old test asserted the two judged rows stay at positions 0 and 1 and the first ten rows keep their order; with one shuffle over the full set a rebuild moves rows. It now asserts each verdict stays on its card, only 2 verdicts exist, the old cards are all still present and no row repeats.
