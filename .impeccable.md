## Validation cadence (authoritative)

For all design-validation questions — "should we show this to testers",
"do we need a user study", "who signs off" — defer to
[docs/validation-philosophy.md](./docs/validation-philosophy.md). That
doc supersedes any "Gate 2 walkthrough" or "Cúpula DT labeler session"
language in older planning docs. Four signals, in order of preference:

1. Automated (tests, telemetry, visual regression, lint)
2. Self-validation (owner-run via dev-browser + screenshots)
3. Informal friends circle when demo-ready
4. Target-community release only after 1-3 have cleared

Do not propose external human validation as a gate for design polish.

## Users

**Who.** Flesh and Blood (FaB) TCG players in the closed Cúpula DT
community (~47 people, Pelotas/RS, Brazil). Mostly competitive amateurs
who already own a physical card collection and track multiple decks.

**Context.** Desktop-first at home for deep deck planning; mobile during
in-person play sessions at local stores and cafés (Gate 2 walkthroughs
happen presencially, not remote). Brazilian Portuguese speakers but app
copy is English today — a concession, not a preference.

**Job-to-be-done.** "What can I play right now given the cards I already
own?" The substitution engine's answer is the entire value prop: a
tracked deck shows how close it is to playable, surfaces what's missing,
and recommends proxies from the user's collection instead of forcing
purchases. The UI is judged by whether a new user can understand this
mental model on first contact, without explanation.

## Brand Personality

Three words: **arcane, tactical, artisanal**.

- **Arcane** — the world of Rathe is high-fantasy occult. Brass,
  parchment, gothic serifs. Hand-set type and restrained ornament belong;
  ◆ diamonds and roman numerals do not — the product-redesign explicitly
  removed both as decoration that carried no meaning. Neon, cyan, pastel
  gradients do not either.
- **Tactical** — this is a decision tool, not a store. Numbers and
  readiness states are the primary content. Visual noise competes with
  comprehension; restraint wins.
- **Artisanal** — signature details are rare and purposeful, not
  sprinkled. The brass readiness display is reserved for one metric. The
  deckbox SVG is hand-tuned, not a stock icon. Where templates would add
  a card-with-icon-and-rounded-corners, we reach for something the
  project actually needs instead.

## Aesthetic Direction

**Theme.** Dark is the primary surface and the default theme. Light is
ported and actively maintained, not deferred — both themes are tone-
corrected and pass the same automated contrast suite
(`apps/web/src/styles/__tests__/contrast.spec.ts`); see
`docs/design/v1/contrast-matrix.md` for the full verified table.

**Palette** (from `apps/web/src/styles/tokens.css`, product-redesign FND-01):
- Dark canvas `#0b0c0f`, surface `#14161c`, surface-2 `#0e1016`
- Brass accent `#d0a84c` — signature color, used on CTAs, focus rings,
  the readiness percent display, active-nav treatment. In dark theme it
  clears AA body contrast on its own, so `--ra-accent-body` is now a
  same-value alias there; light theme keeps a distinct body-safe
  companion (`--ra-accent-body`, `#7d5e1d`) because its accent still
  fails AA body at 4.38:1
- Status palette: ready `#63b678`, warn `#c8843c`, miss `#d0645a`,
  building `#4a7fc0` (first true blue in the system), idea `#8f7cf0`
  (first true violet in the system)
- Seven pitch colors: red, yellow, blue, colorless, weapon (aliases
  colorless), hero, equipment — each with a base swatch (fill/border/dot
  only) and a `-ink` companion (text-safe variant, used for pitch pill
  labels and stat counts)
- Parchment (`#faf3e0`) — shows only on card face illustrations, never
  as a UI surface
- `--ra-ember` (oxblood, `#b44a2e`) is a **legacy token**, kept defined
  for its existing non-deckbox consumers (path-c-result,
  LibraryStatsBar, ReviewsBulkBar, deck detail). It is no longer a
  reserved brand color — the redesigned deckbox has no oxblood in it at
  all — and should not be reached for on new surfaces

**Typography** (Google Fonts, preconnect + async-preload, product-redesign FND-02/03/04):
- **Newsreader** (display, 400–900) — page/deck titles, readiness
  numbers. Supersedes Cinzel and Cinzel Decorative; the redesign has no
  separate decorative-weight tier, so `--ra-font-ornament` is now an
  alias of `--ra-font-display`
- **UnifrakturCook** (fraktur, 700, display-only) — ONE usage: the "R"
  emblem / "Rathe" wordmark on the deckbox logo mark. Never on body copy
- **Hanken Grotesk** (UI, 400/500/600/700) — all interface text:
  labels, buttons, nav, inputs, body, metadata, eyebrows, badges.
  Supersedes IBM Plex Sans
- **IBM Plex Serif** and **JetBrains Mono** — retained unchanged (29 and
  14 file consumers respectively). The redesign's asset list constrains
  what the three families above are used for; it does not mandate
  dropping families it never mentions

**Motion.** Subtle. Shimmer on skeletons, opacity cross-fades on image
load, 180–240ms easing on hover. No bounce, no elastic, no spring
physics in the app shell. The lightbox tilt (perspective + rotateX/Y on
mousemove) is the single "extra" — motion earns its place there.

**References.** Museum exhibit captions. 19th-century card game rule
booklets. Metallic brass embossing on oxblood leather. A hand-set
letterpress invitation.

**Anti-references.**
- Templated admin dashboards (Chakra/MUI defaults, rounded-corner cards
  with icon + heading + body text, identical grid)
- AI-slop aesthetics: cyan-on-dark, purple→blue gradients, neon glows,
  glass morphism as decoration, sparklines-as-ornaments
- SaaS pastel palettes
- Border-left accent stripes on alerts/callouts (banned in impeccable)
- Gradient text (banned)

## Design Principles

1. **Signature treatments stay signature — and there are now two of them.**
   `.ra-readiness-display` (Newsreader 900, fixed brass color via
   `--ra-accent`) survives only on the onboarding congrats screen
   (`CongratsAllPlayable`). Everywhere else readiness is shown by the
   medallion. The redesign's readiness medallion (deckbox face, deck
   detail hero) does **not** reuse `.ra-readiness-display` — its number
   is a fixed cream tone regardless of the surrounding ring's status
   color (`--ready`/`--acc`/`--building`), because a number that changed
   color with the ring would be illegible against some ring colors. That
   medallion number style is owned by its own component, not exposed as
   a shared global utility class.
2. **Both themes' contrast is AA.** All fg/bg pairs, dark and light,
   must clear WCAG AA (4.5:1 body, 3.0:1 large). See
   `docs/design/v1/contrast-matrix.md`.
3. **CSS Modules only in new code.** Zero `style={{}}` on new surfaces.
   Legacy inline styles on untouched files are tolerated until Plan C
   lands the lint rule as an error.
4. **Touch target ≥ 44×44** (R52). Enforced on buttons via
   `min-block-size`/`min-inline-size`.
5. **Focus-visible is 2px brass + 2px gap.** Single declaration:
   `outline: 2px solid var(--ra-accent); outline-offset: 2px`. No
   secondary ring, no shadow-based focus.
6. **`prefers-reduced-motion` is a first-class path.** Every animation
   collapses to a static equivalent under this media query.
7. **Design file is binding.** `docs/design/v1/*.jsx` prototypes are
   the visual reference. The Babel-standalone runtime is NOT copied;
   the structural + typographic choices ARE.
8. **Radii are no longer capped at 4px.** The product-redesign
   supersedes the old "tight/architectural, capped at 4px" rule outright
   — this is a reversal, not a refinement. Current scale: badges 6px,
   small buttons/icons 9px, inputs/buttons 11px, content cards 14px,
   large panels 16px, pills unchanged at full/9999px.
